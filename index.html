Decision2Care

A clinical decision agent whose work-up can be reviewed like a clinician's.

Code on GitHub Paper Watch a work-up
Scroll ↓

A language-model agent just outputs text. Decision2Care records every decision.

Decision2Care is a clinical agent for the patient in the emergency department and intensive care unit that generates no decision as text. At each step a decision model returns a probability for every option, a controller applies a fixed rule, and the step is recorded. A reviewer can see which options were considered and check which result changed the decision.

If agents are to order tests, their work-ups must be auditable.

At morbidity and mortality conferences, clinicians review missed diagnoses by asking what was known at each step and why a test was or was not done. Current LLM agents produce their reasoning and tool calls as text. The transcript shows what the agent did, but its explanation may omit the findings that led to a particular decision.

Options

Which options were considered?

Decision2Care records the probabilities of all the options at each step, so a reviewer can see which options were considered.

Evidence

Which result changed the assessment?

The work-up takes a few seconds, so we can remove or replace a result, re-run the work-up and check which result changed the decision.

Confidence

How sure was the agent?

In MIRA-v2, the best-performing confidence measure requires 5 work-ups of the same case. Decision2Care reads its confidence as one probability after a single work-up.

A work-up as a sequence of typed decisions.

Decision2Care divides a clinical work-up between a decision model and a deterministic controller. The decision model reads the current clinical state and answers typed questions with probabilities rather than text. The controller turns them into actions using fixed rules.

Step 1 of 3

Ask a typed question.

Each step is framed as a question with permitted options, such as the tests that can be ordered or the codes from which the final diagnosis is selected. A Choice asks for a probability for each of a set of named options. A Noul is a yes/no question and asks for the probability that a statement is true.

The decision model scores only the options it is presented with. Its menus therefore cannot contain a hallucinated test, and they are in plain text, so the same model can score new questions without retraining.

Step 2 of 3

Score every option, then act by a fixed rule.

In each round, the decision model reads the current clinical state, which holds the history and the findings retrieved so far. It is given a Choice over the remaining actions, and the controller executes the most probable one, either a tool or the final diagnosis.

Each tool asks further questions to decide what to retrieve, then adds the recorded findings to the clinical state. The tools are services that a hospital already defines: physical examination, vital signs, laboratory tests, imaging and the home medication list. The final diagnosis ends the rounds and is coded by Choices that descend the ICD-10-CM tree from chapter to billable code.

Step 3 of 3

Record every decision.

Decision2Care logs each question, the clinical state used to answer it, the probabilities returned, and the rule applied. A reviewer can then go through the work-up as a sequence of typed decisions and re-ask any question using the state that was recorded at that point.

The decision model answered a mean of 233 typed questions in 14 requests per case.

A decision agent can perform a clinical work-up without generating text.

We ran Decision2Care on 546 emergency admissions to Beth Israel Deaconess Medical Center spanning 12 diseases, taken from MIMIC-IV, and compared it with MIRA-v2, an LLM agent run with GPT-OSS-120B, GLM-5 and Claude Sonnet 5. The same architecture was then used to select treatment and to estimate mortality risk.

Diagnosis · 546 admissions, 12 diseases

Accuracy within the range of LLM agents, in 2.2 seconds per work-up.

Mean diagnostic accuracy was 86.5% for Decision2Care (95% CI 83.6 to 89.2%), within the range of MIRA-v2 with the 3 LLMs (86.1%, 89.9% and 91.7%). More than half of the difference from the 2 stronger configurations came from a single disease, cholecystitis.

A Decision2Care work-up was more than 40 times faster than 1 run of MIRA-v2, at a cost 16 to 61 times lower. Similar accuracies were obtained when 2 other decision models drove the same controller, tools and typed questions in place of Jev, 85.9% with PPLX decider v1.2 and 87.2% with Qwen3.8-Flash-Next.

Differential · after every action

The record shows which result changed the diagnosis.

Across the 546 admissions the true disease was top of the differential in 71.4% of case-runs on the history alone and 93.3% after the work-up. In 10 of the 12 diseases, the largest mean increase in its probability followed a test the guideline uses to make the diagnosis.

In the patient with pain after cholecystectomy, the probability of pulmonary embolism in the differential diagnosis was 0.45 after abdominal CT and 0.96 after chest CT.

In pancreatitis, removing lipase and amylase from the 37 cases that had them lowered accuracy by 54.1 points, whereas removing any other source left it unchanged. The stepwise differential thus showed which diagnoses the agent considered and how each result changed its assessment, while withholding evidence tested whether the final diagnosis depended on it.

Deferral · one work-up

One confidence reading separated correct from incorrect diagnoses about as well as 5 repeated work-ups.

We asked whether the agent could tell, from a single work-up, which of its diagnoses to act on and which to hand to a clinician. MIRA-v2 answers this question with the agreement of 5 repeated work-ups. Decision2Care's signal is its confidence in its diagnosis, one probability queried after a single work-up (AUROC 0.831, compared with 0.827, 0.830 and 0.870).

Decision2Care retained 269 of 546 admissions and correctly diagnosed 265 of those (98.5%). Of the 71 incorrect diagnoses, 67 were in cases flagged for review.

Audit · the 4 errors it retained

Each confident error was traced to one imaging report.

For each of the 4 errors it retained, the audit showed where the work-up went wrong. All 4 were hepatobiliary, and each could be traced to a single imaging report, at which the confidence rose from between 0.23 and 0.47 to between 0.72 and 0.85.

Without that report, repeating diagnostic scoring yielded the correct diagnosis in 3 of the 4 admissions.

Treatment · the same 2 decisions

Drug orders judged guideline-adherent more often than the documented care.

After diagnosis, Decision2Care used the same 2 types of decisions to select the treatment and recorded the steps that led to each order. It first decided whether each medication category or procedure group was indicated, then selected the regimen or procedure, and finally checked each order against the patient's allergies and renal function.

Decision2Care ordered 97.0% of the 1,024 treatments indicated by the rubrics. Averaged over a patient's categories, 88.2% of its drug decisions were judged guideline-adherent (95% CI 86.0 to 90.3%).

Prognosis · 8 disease cohorts

With about half the records, it predicted death as well as three ICU clinicians.

Given the disease, the agent chose, step by step, which records to read and when to stop. For a prediction made 8 h after arrival in the emergency department, it then gave the probability of death within 7, 30 and 90 days, and in the intensive care unit the probability of death before discharge.

At 8 h after arrival, the prediction ranked the patients who died within 30 days with an AUROC of 0.871 in 8,565 entries of 8 disease cohorts from MIMIC-III and MIMIC-IV. With the agent unchanged, the AUROC was 0.813 in 555 patients with pulmonary embolism at Stanford Health Care.

From the ICU clinicians

What three ICU clinicians found when they reviewed the work-ups.

Three ICU clinicians predicted the outcome of 72 cases, selected so that the agent's wrong predictions were over-represented, and then reviewed its work-up.

Records read

The ICU clinicians were given every record offered to the agent, a median of 124 per case, of which the agent had read a median of 54%.

Nothing essential unread

The agent read 1,297 of the 1,397 available records they marked essential for their own predictions. In 196 of their 216 reviews they found no essential record left unread.

At least defensible

When shown the agent's prediction, they rated it as at least defensible in 182 of their 216 reviews. In the same cases, the agent's AUROC did not differ from the ICU clinicians' mean prediction at 30 or 90 days.

In the ICU, 12 h of records were enough to exceed 3 severity scores computed at 24 h in intracerebral haemorrhage and traumatic brain injury (AUROC 0.874 and 0.872). In the other 6 ICU cohorts, the prediction from 12 h of records did not differ from the severity scores computed at 24 h.

One interface for diagnosis, treatment and prognosis.

Diagnosis, treatment and prognosis all use the same interface and differ in their action menus, execution rules and endpoints.

decision model
Unless stated otherwise, the decision model is Jev, developed by TypeSafe AI. It can be replaced by another decision model without changing the controller or the questions.
controller
The controller applies fixed rules to the returned probabilities. It executes the most probable action, and orders a test when its probability reaches 0.5.
tools
Physical examination, vital signs, laboratory tests, imaging and the home medication list. Each tool asks further questions to decide what to retrieve.
audit record
The saved work-up record links the questions, the returned probabilities, the rule the controller applied, the executed actions, the returned observations and the final code.
treatment
After the final diagnosis, a Noul for each medication and procedure category selects the indicated options. Choices then select the drug regimen with its dose, route and frequency, the action on each home medication and the ICD-9-CM procedure.
on site
Two alternatives to Jev reached comparable diagnostic accuracy and ran on a single NVIDIA DGX Spark. A hospital could run the agent on that hardware and keep its patient records on site.

What the evaluation does not show.

  • The evaluation was retrospective. Prospective studies would be needed to assess how clinicians use the agent, how much case review costs and whether there is any patient benefit.
  • We evaluated diagnostic confidence as a ranking score. Its calibration would need to be assessed in the target population, and thresholds for diagnostic confidence and mortality prediction established and validated there.
  • Decision2Care can be confident in a wrong diagnosis. In every instance where the agent retained a wrong diagnosis, the audit traced the increase in confidence back to a single imaging report.
  • The agent read the radiologist's report and not the images.
  • Early decisions to limit care are associated with death, and a mortality prediction may partly reflect those decisions if they are recorded in the chart.
  • Clinicians determine what to do in response to the agent's diagnoses, suggested orders and predictions.

Run Decision2Care yourself.

The core source code for Decision2Care, including diagnosis, treatment selection and mortality prediction, is publicly available. The released code includes the wording of every question, prompt and answer option.

  1. Install

    Python 3.10 or newer.

    git clone https://github.com/peterhan91/Decision2Care.git
cd Decision2Care
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'

  2. Run the three synthetic examples

    No model account or patient data is needed. The synthetic run verifies execution, logging and the input and output contracts. Its outputs are protocol tests, not clinical predictions or reproduced benchmark scores.

    bash scripts/run_synthetic.sh
python -m pytest -q

  3. Run on records

    Live runs need access to the decision model and credentialed clinical data. The repository's README gives the full commands.

    python -m pip install -e '.[live]'
# with TYPESAFE_API_KEY set and authorized records in place
decision2care diagnosis  ...
decision2care treatment  ...
decision2care prognosis  ...
